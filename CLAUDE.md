# quilt

Self-hosted PaaS: pools your servers into one k3s cluster, runs apps on Knative with scale to zero. TypeScript monorepo (npm workspaces + Turborepo).

@AGENTS.md

## Commands

```bash
npm run infra:start              # Postgres 18 (:5432) + RustFS S3 (:9000) via docker compose
npm run dev:server               # API on :3000 (also dev:web, dev:controller)
npm run check                    # biome check --write
npx turbo run check-types test   # what the pre-commit hook runs
npm run test:integration         # needs infra:start; each run creates and drops its own DB and bucket
npx turbo run test -- --coverage.enabled   # lcov in <pkg>/coverage/unit (test:integration → coverage/integration)
mise run cluster:dev:up          # k3d cluster + Knative, needed for test:e2e
npx turbo boundaries             # CI fails on imports of undeclared deps or across package dirs
```

Database (run drizzle-kit through the workspace, not the root script):

```bash
npm run db:generate -w @quilt/db -- --name <change>   # after editing packages/db/src/schema
npm run db:migrate -w @quilt/db                         # apply to the dev DB (DATABASE_URL in apps/server/.env.development)
```

## Layout

| Path | Role |
|---|---|
| `apps/server` | Express host for the API: oRPC at `/rpc`, OpenAPI REST at `/api-reference`, Better Auth at `/api/auth` |
| `apps/web` | Dashboard: Vite, TanStack Router/Query/Form, shadcn/ui from `packages/ui` |
| `apps/cli` | `quilt` CLI (citty), calls the same API |
| `apps/controller` | Reconciles apps into cluster workloads (`packages/cluster`) |
| `apps/docs` | Fumadocs site; API reference generated from `packages/api` |
| `apps/e2e` | Vitest e2e against a real server, controller and k3d cluster |
| `packages/api` | oRPC routers (`src/routers`) and business logic (`src/services`) |
| `packages/auth` | Better Auth config with the organization plugin |
| `packages/db` | Drizzle schema and migrations (Drizzle 1.0 RC, relations v2) |
| `packages/storage` | The only package that touches the S3 SDK |

## Conventions

- Routers stay thin: services throw typed errors (`OrganizationNotFoundError`, ...), routers map them to declared oRPC errors built with `describeErrorResponse`.
- Org-scoped endpoints name the org in the path (`/orgs/{org}/...`) and resolve it with `getMemberOrganization`. `activeOrganizationId` is UI-only; never read it in the API.
- Paginated endpoints use `PageInput`/`pageOf`; clients consume them with oRPC `infiniteOptions`.
- Image uploads go through `replaceImage` (`services/images.ts`) with an `ImageSlot` prefix ending in `/`, plus `ImageFile`/`invalidImage`/`describeImageUpload` from `routers/images.ts`. The object key is what gets stored in the DB column.
- Object storage only through `@quilt/storage` (`putObject`, `getObject`, `deleteObject`).
- `@quilt/db/testing` and `@quilt/storage/testing` are test-only; Biome rejects them in application code.
- API integration tests use the fixtures in `packages/api/src/testing/fixtures.ts` (`db`, `storage`, `auth`, `signUp`, `createOrganization`) and run against real Postgres, RustFS and Better Auth.

## Gotchas

- Root `npm run db:*` scripts are Turborepo `interactive` tasks and fail outside a real terminal; use the `-w @quilt/db` forms above.
- Env vars are declared in each package's `.env.schema` (varlock). After changing one, run `npm run env:generate`; never edit the generated `src/env.ts`.
- `packages/db/src/schema/auth.ts` is generated by `npm run auth:generate` (Better Auth CLI); change the auth config instead of editing it.
- Commits are conventional and commitlint-checked; valid scopes are workspace directory names plus `infra`, `deps`, `ci`, `release`, `repo`.
- `e2e.yml` is not yet a required check; it runs but doesn't gate merges.
- Pass `--coverage.enabled`, not `--coverage`, through Turborepo: the bare flag replaces the whole coverage config and drops each package's `reportsDirectory`.
- Codecov judges PRs on patch (changed-line) coverage, informational only; see `codecov.yml`.
